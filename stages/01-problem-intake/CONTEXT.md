# Stage 01: Problem Intake

Frame a rough product problem as a researchable UX challenge.

## Inputs

| Source | File/Location | Section/Scope | Why |
|--------|--------------|---------------|-----|
| User | Conversation | Problem, idea, audience, constraints | Starting point for the run |
| Shared context | `../../SOUL.md` | Full file | Workspace credo |
| Shared context | `../../shared/project-profile.md` | Workspace Defaults | Default project settings |
| Reference | `references/intake-format.md` | Full file | Output structure |

## Process

1. Clarify the user's rough problem, idea, or brief.
2. Create a lowercase project slug such as `curry-cruiser`.
3. Separate facts, assumptions, open questions, and desired outcomes.
4. Identify target users, context, constraints, and success signals.
5. Write research questions for Stage 02.
6. Run the audit, revise if needed, then save to output/.

## Checkpoints

| After Step | Agent Presents | Human Decides |
|------------|---------------|---------------|
| 3 | Problem frame, assumptions, constraints | Whether the framing is accurate enough for research |

## Audit

| Check | Pass Condition |
|-------|---------------|
| Problem clarity | Problem is specific enough to research but does not prescribe a solution |
| Assumption labeling | Facts, assumptions, and open questions are separate |
| Research readiness | Stage 02 has concrete research questions |

## Outputs

| Artifact | Location | Format |
|----------|----------|--------|
| Project brief | `output/[project-slug]-project-brief.md` | Markdown brief |
