# Stage 04: Define Artifacts

Define the UX problem, hypotheses, and value proposition.

## Inputs

| Source | File/Location | Section/Scope | Why |
|--------|--------------|---------------|-----|
| Research | `../02-research-and-validation/output/[project-slug]-research-dossier.md` | Full file | Evidence and assumptions |
| Previous stage | `../03-empathize-artifacts/output/[project-slug]-empathize-artifacts.md` | Full file | User synthesis |
| Skill reference | `../../skills/design-thinking/references/define.md` | Full file | Define formats |
| Shared context | `../../SOUL.md` | Full file | Workspace credo |

## Process

1. Review research and empathize artifacts.
2. Write problem statements and user needs statements.
3. Write hypothesis statements and problem/hypothesis pairs.
4. Write the value proposition.
5. Check that definitions do not prescribe a solution too early.
6. Write only the exact content sections from `Definition Brief Structure`.
7. Run the audit, revise if needed, then save to output/.

## Checkpoints

| After Step | Agent Presents | Human Decides |
|------------|---------------|---------------|
| 4 | Definition brief draft | Which problem frame should guide ideation |

## Audit

| Check | Pass Condition |
|-------|---------------|
| User need focus | Statements describe user needs, not features |
| Testability | Hypotheses include observable outcomes |
| Value clarity | Value proposition names user, problem, outcome, and difference |
| Artifact focus | Output uses only the exact Definition Brief Structure sections |
