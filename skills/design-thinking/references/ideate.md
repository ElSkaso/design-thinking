# Ideate Reference

Use this reference to generate solution directions from a defined problem.

## Ideation Principles

- Generate quantity before narrowing.
- Keep the problem statement visible.
- Explore multiple solution shapes before selecting one.
- Include accessibility and edge cases in ideation, not only after design.
- Evaluate ideas against evidence, value, feasibility, and user fit.

## Competitive Audit

Use a competitive audit to understand alternatives, market expectations, and gaps.

Include direct competitors, indirect competitors, and user workarounds.

Audit dimensions:

- Audience and positioning
- First impression
- Core workflow
- Interaction patterns
- Accessibility
- Visual design
- Content and messaging
- Pricing or business model when relevant
- Strengths
- Weaknesses
- Gaps/opportunities

Output format:

```markdown
## Competitive Audit Summary
- Audit goal:
- Competitors reviewed:
- Direct competitors:
- Indirect competitors:
- Common patterns:
- Notable strengths:
- Notable weaknesses:
- Market gaps:
- Implications for our product:
- Risks of copying competitors:
```

Quality check:

- Includes both direct and indirect competitors.
- Compares product behavior, not only visuals.
- Identifies gaps connected to user needs.
- Avoids treating competitor norms as automatic best practice.

## Goal Statements

Goal statements connect user needs to product direction.

Template:

```text
Our [PRODUCT_OR_CONCEPT] will let users [PRIMARY_ACTION] so they can [USER_OUTCOME]. We will measure success by [SUCCESS_SIGNAL].
```

Review:

- Is the user outcome clear?
- Does the statement avoid implementation details?
- Does it name how success could be measured?

## How Might We Questions

HMW questions turn problems into opportunity spaces.

Good HMW questions are:

- Broad enough to allow multiple answers
- Narrow enough to guide ideation
- Collaborative in tone
- Grounded in the defined problem

Ways to generate HMWs:

- Amplify a positive behavior.
- Remove or reduce a pain point.
- Reverse a negative assumption.
- Break a complex problem into smaller moments.
- Change the process entirely.
- Borrow from an analogous experience.
- Use a new resource or technology.

Template:

```text
How might we [HELP_OR_ENABLE] [USER_OR_SEGMENT] to [OUTCOME] when [CONTEXT_OR_CONSTRAINT]?
```

## Rapid Sketching And Crazy Eights

Use rapid sketching to produce many UI or workflow concepts quickly.

Process:

1. Pick one problem statement or HMW question.
2. Generate eight distinct solution sketches or screen concepts.
3. Give each sketch a short label and rationale.
4. Cluster similar ideas.
5. Select promising directions based on user value, evidence, feasibility, and accessibility.

Text-only output format:

```markdown
## Rapid Sketch Set: [HMW_OR_PROBLEM]
1. Sketch label:
   - Screen/workflow idea:
   - User value:
   - Risk:
2. ...

## Selection
- Strongest directions:
- Combined idea:
- Why this direction fits the evidence:
```

## Wireframe Framing

Wireframes should express structure, priority, and workflow before high-fidelity styling.

Include:

- Screen list
- Primary user flow
- Key content per screen
- Main actions
- Empty, loading, error, and success states when relevant
- Accessibility considerations
- Notes that tie layout choices to research findings

## Ideate Audit

- Ideas trace back to a problem statement or HMW.
- Competitive audit identifies gaps, not just examples to copy.
- Multiple solution directions were considered.
- Wireframe requirements cover real user flows and states.
- Selected direction is justified by evidence, feasibility, and user value.
