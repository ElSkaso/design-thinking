# Prototype And Test Reference

Use this reference when design thinking work moves into prototype planning or usability testing.

## Prototype Scope

Define prototype scope before building.

Include:

- Prototype goal
- Target users
- Primary task flow
- Screens or states needed
- Interactions required
- Data assumptions
- Non-goals
- Fidelity level
- Tool or implementation target

Template:

```markdown
## Prototype Scope
- Goal:
- Target users:
- Primary task:
- Screens:
- Required interactions:
- Data assumptions:
- Non-goals:
- Fidelity:
- Success criteria:
```

## From Wireframes To App Requirements

When moving toward a functioning app, translate UX artifacts into:

- User flows
- Route map
- Component responsibilities
- Data model assumptions
- State handling
- Content requirements
- Accessibility requirements
- Responsive behavior
- Test scenarios

Keep the requirements tied to design intent. Do not invent features that were not supported by the research or checkpoint decision.

## Usability Test Plan

Include:

- Research question
- Participants
- Scenario
- Tasks
- Success criteria
- Observation checklist
- Follow-up questions
- Risks or bias controls

Task format:

```text
You are [USER_CONTEXT]. Use the prototype to [TASK_GOAL].
```

Observe:

- Completion
- Time or effort
- Confusion
- Misclicks or dead ends
- Language users use
- Accessibility friction
- Workarounds

## Test Synthesis

After testing, summarize:

- What worked
- What failed
- Where users hesitated
- Which assumptions were validated
- Which assumptions were invalidated
- Recommended design changes
- Severity of each issue

## Prototype/Test Audit

- Prototype scope matches the selected design direction.
- Test tasks are realistic and not leading.
- Success criteria are observable.
- Findings distinguish evidence from interpretation.
- Recommended changes connect to user behavior.
